## 23.11.2026 — полное логирование и документация кода

### Журналирование

- Три журнала: `mosaic.access` (строка на запрос), `mosaic.server`
  (запуск, ошибки, трассировки), `mosaic.audit` (вход, регистрация,
  загрузка, удаление, комментарии, сообщения).
- В строке доступа появились имя пользователя, время выполнения и
  идентификатор запроса; идентификатор возвращается в `X-Request-Id`.
- Медленные запросы (> 1 с) отмечаются предупреждением, ответы 5xx
  дублируются в журнал ошибок.
- Параметр `--log-level` и поле `log_level` в `config.json`.
- Новый модуль `server/core/logging_setup.py`; настройка вынесена из
  `main.py`.

### Документация кода

- Подробные docstring'и с разделами Args/Returns/Raises для классов и
  методов серверных модулей: `config`, `core/*`, `http/*`, `api/*`,
  `db/*`, `app`, `main`.
- Комментарии к неочевидным местам: порядок заголовков, WAL, SO_REUSEADDR,
  проверка порта, `py_lower`, безопасное закрытие сокета.

### Проверки

## 23.11.2026 — комментарии, поиск по подписям, доступ с другого ПК

### Новые возможности

- **Просмотр фотографии крупным планом.** Щелчок по карточке открывает
  модальное окно: изображение, автор, подпись, лайки, кнопка скачивания.
- **Комментарии.** Таблица `comments`, маршруты `GET/POST
  /api/posts/{id}/comments`, счётчик на карточке, добавление без перезагрузки.
- **Скачивание.** `GET /api/posts/{id}/download` отдаёт файл с
  `Content-Disposition: attachment`.
- **Поиск по подписям.** `GET /api/search` возвращает людей и публикации;
  клиент показывает секции «Люди» и «Публикации» с миниатюрами.
- **«Мой профиль».** Пункт «Профиль» в шапке открывает все свои публикации.
- **Удаление постов.** Автор удаляет свою публикацию кнопкой «Удалить»
  в окне фото; запись, лайки, комментарии и файл удаляются.

### Доступ с другого компьютера

- `scripts/allow_firewall.bat` — добавление правила брандмауэра
  с самоповышением прав.
- `scripts/start_server_public.bat` — правило и запуск сервера в один клик.
- `scripts/check_network.bat` — диагностика: запущен ли сервер, есть ли
  правило, какие адреса и какой из них открывается снаружи.
- Общий модуль `server/core/network.py` сортирует адреса так, чтобы
  первым шёл адрес Wi-Fi/Ethernet, а не виртуальный адаптер.
- Сервер сам проверяет занятость порта: второй экземпляр не запустится
  и не будет перехватывать запросы (на Windows SO_REUSEADDR это позволял).

### Демо-данные и сохранность

- Остались только `ksenia` и `artem`; у каждого по три публикации,
  пять комментариев и переписка между ними.
- `seed_demo.py --reset` больше не удаляет базу: она сохраняется как
  `storage/mosaic-backup-<дата>.db`, загруженные файлы не трогаются.

### Тесты и документы

- 77 тестов (добавлены `test_comments.py`: комментарии, поиск по подписи,
  скачивание; `test_api.py`: удаление своей и чужой публикации).

## 22.11.2026 — сборка проекта

### Ядро сервера

- `server/config.py` — конфигурация из трёх источников, проверка параметров.
- `server/http/request.py` — собственный парсер HTTP/1.1: стартовая строка,
  заголовки без учёта регистра, тело по `Content-Length`, query string,
  cookie, лимиты заголовков и тела.
- `server/http/response.py` — сборка ответа, `Set-Cookie`, `Connection: close`,
  статусы и причины.
- `server/http/multipart.py` — разбор `multipart/form-data` по байтам,
  поддержка `filename*`, ограничение числа частей.
- `server/http/router.py` — шаблоны `{name}`, 404 и 405 с `Allow`.
- `server/core/server.py` — `accept`, поток на соединение, таймаут 30 с,
  журнал доступа, вежливое закрытие при 413.
- `server/core/sessions.py` — токены `secrets.token_urlsafe(32)`, срок 7 дней,
  очистка просроченных.
- `server/core/security.py` — PBKDF2-HMAC-SHA256 (200 000 итераций),
  валидация, `safe_join`, определение формата по сигнатуре.
- `server/core/storage.py` — сохранение файлов под UUID через временный файл.
- `server/db/database.py` — соединение на поток, WAL, внешние ключи,
  функция `py_lower` для регистронезависимого поиска по кириллице.
- `server/db/repository.py` — все SQL-запросы, лента одним запросом,
  переключатель лайков, диалоги через CTE.
- `server/api/*` — регистрация, вход, лента, загрузка, лайки, поиск,
  сообщения и отметка о прочтении.

### Клиент

- `web/index.html`, `web/login.html` — SPA с шаблонами `template`.
- `web/style.css` — мозаичная раскладка на CSS-колонках, адаптивность,
  модальный диалог загрузки.
- `web/app.js` — лента, пагинация, лайки, поиск, профиль, сообщения
  с опросом раз в 3 секунды; вставка данных только через `textContent`.
- `web/auth.js` — вход и регистрация.
- `client_raw/raw_client.py` — консольный HTTP-клиент на сокетах.

### Исправленные дефекты

1. Поиск не находил кириллицу — SQLite `LIKE` и `COLLATE NOCASE` работают
   только с латиницей; добавлена функция `py_lower`.
2. Ответ 413 терялся из-за RST — добавлено дочитывание тела перед закрытием.
3. Текст в списке диалогов накладывался — flex, `overflow` и `ellipsis`.
4. Кракозябры в консоли Windows — `PYTHONUTF8` и `reconfigure` потоков.
5. Строки доступа содержали префикс `INFO` — у каждого логгера свой форматтер.
6. Кириллица в query не кодировалась в тестовом клиенте — добавлен `quote`.
