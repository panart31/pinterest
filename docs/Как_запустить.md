# Как запустить «Мозаику» — инструкция для чайников

Эта инструкция рассчитана на человека, который ни разу не запускал сервер.
Все команды вводятся в **командную строку Windows** (`cmd`), а не в PowerShell,
если не сказано иное. Копируйте команды целиком.

---

## 0. Что мы вообще запускаем

«Мозаика» состоит из двух частей:

| Часть | Что это | Где лежит |
|---|---|---|
| Сервер | программа на Python, слушает порт 8000 | `server/main.py` |
| Клиент | обычный браузер (Chrome, Edge, Firefox) | открывает адрес сервера |

Сервер — **один процесс**. Он принимает TCP-соединения, сам разбирает HTTP
и отдаёт страницы, картинки и JSON. База данных и фотографии лежат в папке
`storage/` внутри проекта.

Есть два режима работы:

1. **Один компьютер** — сервер и браузер на одной машине, адрес
   `http://127.0.0.1:8000`.
2. **Два устройства в одной сети** — сервер на ноутбуке, клиент на телефоне
   или втором ноутбуке, адрес `http://<IP-сервера>:8000`.

Для курсовой нужен именно второй режим: преподаватель хочет видеть
клиент-серверное приложение на двух устройствах. Интернет при этом
**не нужен** — достаточно одной Wi-Fi-сети или точки доступа телефона.

## 1. Подготовка (делается один раз)

### Шаг 1.1. Откройте папку проекта

Папка называется `pinterest` и лежит по пути:

```bat
C:\Users\User\source\repos\pinterest
```

Если проект перенесли в другое место — дальше везде подставляйте свой путь.

### Шаг 1.2. Проверьте Python

Нажмите `Win + R`, введите `cmd`, нажмите Enter. В чёрном окне введите:

```bat
py -V
```

Должно появиться что-то вроде:

```text
Python 3.14.6
```

Подойдёт любая версия **3.10 или новее**.

Если пишет `'py' не является внутренней или внешней командой` — попробуйте:

```bat
python -V
```

Если и это не работает или открылся Microsoft Store — установите Python
с сайта [python.org](https://www.python.org/downloads/), при установке
обязательно поставьте галочку **Add Python to PATH**, после установки
закройте и снова откройте командную строку.

> На этом компьютере `python` — заглушка Microsoft Store, поэтому везде
> используем `py`. Если у вас работает `python` — можно писать `python`.

### Шаг 1.3. Ничего устанавливать не нужно

Сервер использует только стандартную библиотеку Python. `pip install`
для запуска **не требуется**. Пакеты нужны только для тестов (`pytest`)
и сборки документов (`python-docx`, `matplotlib`), но они уже установлены
на этом компьютере.

## 2. Запуск на одном компьютере

### Вариант А — двойной щелчок (самый простой)

1. Откройте папку проекта в проводнике.
2. Зайдите в папку `scripts`.
3. Дважды щёлкните `run_server.bat`.

Откроется чёрное окно, включится UTF-8, и появится примерно такой баннер:

```text
========================================================
  Мозаика — сервер запущен
========================================================
  На этом ПК:      http://127.0.0.1:8000
  С другого ПК:    http://192.168.1.127:8000
  База:            C:\...\pinterest\storage\mosaic.db
  Файлы:           C:\...\pinterest\storage\uploads
  Журнал:          C:\...\pinterest\server.log (INFO)
  Остановка:       Ctrl+C
========================================================
```

### Вариант Б — командная строка

```bat
cd /d C:\Users\User\source\repos\pinterest
py server/main.py --host 0.0.0.0 --port 8000
```

Результат тот же.

### Шаг 2.1. Откройте сайт

В браузере введите:

```text
http://127.0.0.1:8000
```

Должна открыться страница входа «Мозаика» с розовым логотипом.

Если страница не открылась — смотрите раздел 7 «Если что-то не работает».

### Шаг 2.2. Зарегистрируйтесь

1. Нажмите «Регистрация».
2. Логин: латиница, 3–32 символа, например `test1`.
3. Пароль: не короче 6 символов.
4. Отображаемое имя: любое, например «Тестовый пользователь».
5. Нажмите «Создать аккаунт».

После регистрации откроется пустая лента. Это нормально: фотографий пока нет.

### Шаг 2.3. Загрузите первое фото

1. Нажмите «Загрузить» (или «+» в шапке).
2. Выберите файл JPEG, PNG, GIF или WEBP до 5 МБ.
3. Напишите подпись, например «Первый тест».
4. Нажмите «Опубликовать».

Фото появится в ленте. Если появилось — сервер, база и хранилище работают.

## 3. Демонстрационные данные (аккаунты Ксении и Артёма)

В проекте есть скрипт, который создаёт двух пользователей, шесть фотографий,
комментарии и переписку. Это удобно для показа на защите.

**Важно:** скрипт нужно запускать при **остановленном** сервере. Если сервер
работает, скрипт честно скажет, что база занята.

1. Остановите сервер: в окне сервера нажмите `Ctrl+C`.
2. В командной строке:

```bat
cd /d C:\Users\User\source\repos\pinterest
py scripts/seed_demo.py --reset
```

3. Снова запустите сервер (`scripts\run_server.bat`).
4. Войдите:

| Логин | Пароль | Кто это |
|---|---|---|
| `ksenia` | `secret123` | Ксения Дутикова |
| `artem` | `secret123` | Артём Панов |

`--reset` **не удаляет** старую базу безвозвратно: рядом появляется копия
`storage/mosaic-backup-<дата>.db`. Загруженные фотографии тоже остаются.

Откройте сайт и пройдите по списку. Напротив каждого пункта — что должно

|---|---|---|

| 5 | Поставить лайк | Сердечко закрашивается, счётчик увеличивается |
| 6 | В поиске ввести `закат` | Находится фотография с подписью «Закат на набережной…» |
| 7 | В поиске ввести `Ксения` | Находится пользователь `ksenia` |
| 8 | Нажать «Профиль» | Показаны только свои публикации |
| 9 | Открыть своё фото → «Удалить» | Фото исчезает из ленты и с диска |

## 5. Запуск со второго устройства (телефон или ноутбук)

### Шаг 5.1. Запустите сервер «для сети»

Дважды щёлкните:

```bat
scripts\start_server_public.bat
```

Появится запрос прав администратора — нажмите «Да». Скрипт:

1. добавляет правило брандмауэра для порта 8000;
2. показывает IPv4-адреса компьютера;
3. запускает сервер на `0.0.0.0:8000`.

В баннере найдите строку **«С другого ПК»**:

```text
  С другого ПК:    http://192.168.1.127:8000
```

Это и есть «ссылка» на сайт. Домена у него нет — только IP-адрес.

### Шаг 5.2. Подключите второе устройство

1. Телефон и ноутбук должны быть в **одной Wi-Fi-сети**.
2. На телефоне откройте браузер и введите адрес из баннера:
   `http://192.168.1.127:8000`.
3. Должна открыться та же страница входа.

### Шаг 5.3. Если не открывается

Запустите диагностику:

```bat
cd /d C:\Users\User\source\repos\pinterest
py scripts/check_network.py
```

Скрипт покажет:

- работает ли сервер на порту 8000;
- есть ли правило брандмауэра;
- все адреса компьютера и какие из них отвечают;
- какой адрес открывать на втором устройстве.

Типичные причины:

| Причина | Что делать |
|---|---|
| Windows спросила про доступ к сети, вы нажали «Отмена» | снова запустите `start_server_public.bat` и разрешите |
| Телефон в «гостевой» Wi-Fi | переключитесь на обычную сеть или точку доступа телефона |
| Wi-Fi изолирует клиентов | раздайте интернет с телефона и подключите ноутбук к нему |
| Выбран адрес виртуального адаптера (VMware, Docker, WSL) | возьмите адрес Wi-Fi/Ethernet, где написано «подходит» |
| Сервер слушает только `127.0.0.1` | запустите с `--host 0.0.0.0` или через `start_server_public.bat` |
| Брандмауэр блокирует | `scripts\allow_firewall.bat` от имени администратора |

Проверить связь можно с телефона: откройте `http://<IP>:8000` ещё раз после
перезапуска сервера. С ноутбука — `ping <IP>`.

### Про «локальность» и интернет

По требованиям курсовой приложение должно быть **клиент-серверным** и
демонстрироваться на **двух устройствах в одной локальной сети**. Публичный
сайт в интернете не требуется. Наша схема полностью этому соответствует:

- сервер — один компьютер;
- клиент — браузер на другом устройстве;
- обмен идёт по TCP/IP по локальной сети;
- данные хранятся на компьютере-сервере.

Если очень нужно показать сайт человеку из другой сети, можно поднять
временный туннель через `cloudflared` (см. README). Для защиты это не нужно.

## 6. Где хранятся данные и почему они не пропадают

Все пути привязаны к **корню проекта**, а не к текущему каталогу. Поэтому
сервер можно запускать из любого места — он всё равно найдёт свою базу.

| Что | Путь |
|---|---|
| База SQLite | `storage/mosaic.db` |
| Фотографии | `storage/uploads/<uuid>.png` (или `.jpg`, `.gif`, `.webp`) |
| Журнал | `server.log` |
| Настройки | `config.json` |

Что важно знать:

1. **Не удаляйте папку `storage/`** — вместе с ней пропадут аккаунты и фото.
2. Файлы называются случайными UUID, исходное имя не используется.
3. При удалении публикации файл тоже удаляется.
4. `seed_demo.py --reset` делает резервную копию базы, а не стирает её.
5. Если фотографии «пропали» после перезапуска — почти всегда сервер был
   запущен с другим `--db` или `--uploads`, либо из другой копии проекта.
   Проверьте строки «База» и «Файлы» в баннере: они должны указывать внутрь
   `C:\Users\User\source\repos\pinterest\storage`.

Резервная копия вручную: остановите сервер и скопируйте всю папку `storage`
в надёжное место. Этого достаточно.

## 7. Остановка и повторный запуск

### Остановить

В окне сервера нажмите `Ctrl+C`. Появится «Остановка сервера…», окно можно
закрыть.

Если окно потерялось, найдите процесс:

```bat
netstat -ano | findstr :8000
```

В последней колонке будет PID, например `12345`. Затем:

```bat
taskkill /F /PID 12345
```

### Запустить снова

```bat
cd /d C:\Users\User\source\repos\pinterest
scripts\run_server.bat
```

или снова двойным щелчком. Все аккаунты, фото и сообщения останутся на месте.

### Если порт занят

В баннере будет ошибка «Не удалось занять 0.0.0.0:8000». Варианты:

1. Закрыть старый экземпляр сервера (см. выше).
2. Запустить на другом порту:

```bat
py server/main.py --host 0.0.0.0 --port 8001
```

Тогда адрес будет `http://127.0.0.1:8001` (и `http://<IP>:8001` для второго
устройства). Не забудьте про брандмауэр для нового порта.

## 8. Тесты и консольный клиент

### Тесты

```bat
cd /d C:\Users\User\source\repos\pinterest
py -m pytest -q
```

Ожидаемая последняя строка:

```text
79 passed
```

Тесты поднимают собственный сервер на свободном порту и используют
временную базу, поэтому работающий сервер им не мешает. Но если вы
запускаете тесты во время демонстрации, лучше остановить основной сервер,
чтобы не путать окна.

### Консольный клиент на голых сокетах

Он доказывает, что клиент умеет HTTP без браузера и без библиотек:

```bat
py client_raw/raw_client.py login ksenia secret123
py client_raw/raw_client.py feed
py client_raw/raw_client.py send artem "Привет!"
py client_raw/raw_client.py upload photo.jpg "Подпись"
```

Клиент сохраняет cookie в `client_raw/.session`.

## 9. Журналы: что и где смотреть

Сервер пишет **в консоль и в `server.log`** одновременно. Есть три журнала:

| Журнал | Что пишет |
|---|---|
| `mosaic.access` | одна строка на каждый запрос: IP, пользователь, метод, путь, код, размер, время, `id` запроса |
| `mosaic.server` | запуск, конфигурация, ошибки сервера, остановка |
| `mosaic.audit` | вход, регистрация, загрузка, удаление, комментарии, сообщения |

Пример строки доступа:

```text
192.168.1.50 - ksenia [23/Nov/2026 14:05:12] "POST /api/posts HTTP/1.1" 201 24576 18ms id=3f2a9c1e
```

Что она значит:

- `192.168.1.50` — с какого устройства пришёл запрос;
- `ksenia` — кто был авторизован;
- `POST /api/posts` — что запросили;
- `201` — код ответа (успех);
- `24576` — размер ответа в байтах;
- `18ms` — сколько заняла обработка;
- `id=3f2a9c1e` — идентификатор запроса, он же в заголовке `X-Request-Id`.

Повысить подробность:

```bat
py server/main.py --log-level DEBUG
```

Найти ошибки в журнале:

```bat
findstr /I "ERROR WARNING" server.log
```

## 10. Частые проблемы и решения

| Симптом | Причина | Решение |
|---|---|---|
| `'py' не является внутренней командой` | Python не установлен или не в PATH | установить Python 3.10+, галочка Add to PATH |
| Открылся Microsoft Store вместо Python | заглушка Windows | установить настоящий Python с python.org |
| `Не удалось занять 0.0.0.0:8000` | порт занят | `--port 8001` или `taskkill` старый процесс |
| Страница не открывается даже на своём ПК | сервер не запущен или упал | смотреть консоль и `server.log` |
| С телефона не открывается | брандмауэр, гостевая Wi-Fi, изоляция клиентов | `start_server_public.bat`, `check_network.py`, точка доступа телефона |
| Вместо русского текста — кракозябры | консоль не в UTF-8 | запускать через `run_server.bat` или `set PYTHONUTF8=1` |
| Старый интерфейс после правок | кэш браузера | `Ctrl+F5` |
| `database is locked` | два сервера на одной базе | закрыть лишний экземпляр |
| Фото не видно после перезапуска | другой `--db`/`--uploads` или другая копия проекта | проверить пути в баннере, не удалять `storage/` |
| `no such table` | база не создана или указан чужой файл | удалить/переименовать пустой файл, запустить сервер снова |
| Тесты падают | запущены из другой папки | `cd /d C:\Users\User\source\repos\pinterest` |
